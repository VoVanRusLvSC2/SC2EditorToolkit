Поле actualTimeMs читается из индикатора Scene Time с точностью 10 мс.
Штатная команда Next Frame проверенной сборки продвигает таймлайн на 33 мс.
Кадры берутся из исходного рендера без изменения времени ради получения
нечёрного изображения. Во время прогрева допускается несколько захватов на
том же остановленном времени; чёрный/однотонный результат остаётся ошибкой.

Компиляция Nydus после катсцены вернула прежние **341 732 байта** Galaxy и SHA-256:
`0e06ea0c8a379af32fa5372a2a373353646031282f09b305b38c29de09b16aa3`.
Существующий модуль генерации/компиляции не заменён и продолжает работать.

Воспроизводимый opt-in сценарий: `tests/live_cutscene.py --package --compile-after`
с аргументами --template, --scene, --camera, --work. Полные локальные результаты,
PNG, runtime state и токены не входят в репозиторий или релиз.

Galaxy Nydus — **341 732 байта**, SHA-256:
`0e06ea0c8a379af32fa5372a2a373353646031282f09b305b38c29de09b16aa3`.
Побайтно совпал с результатом ранее проверенного оригинального редактора.
В новом модульном API используется тот же нативный XML pipeline.

Результат PNG подтверждает транспорт из оригинального рендера, но **не** снимок
заданного ролика. Содержательной сцены в этом тесте не выбрано. Кадр чёрный;
это явно отражено в API. Управление таймлайном, камерой и выбор нужного viewport
оставлены следующим модулем и не выдаются за готовую функциональность.

Логический focus внутри приватного desktop нужен оригинальному Editor для
правильной авторской библиотеки и обновления команд. Его события отделены от
foreground рабочего стола пользователя. Мышь/клавиатура не инжектируются.

Живые моды, полные журналы, токены, runtime state и изображения пользовательского
контента не входят в Git. Скрипты opt-in тестирования находятся в `tests/`.
