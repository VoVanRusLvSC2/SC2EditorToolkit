# Проверка v0.5.0 — 2026-10-20

Финальные windowed API/MCP EXE, Windows x64; оригинальный SC2 Editor
5.0.17.98310. Nydus v153 Local и его установленные зависимости, приватная копия.

| Проверка финального EXE | Результат |
|---|---|
| NydusIntroBlue, исходный файл, диапазон 990–1320 мс | PASS, 5 кадров / 15 FPS, H.264 + AAC |
| Полная приватная копия Nydus с native Marine_Ready, элемент с 500 мс | PASS, 40 кадров / 10 FPS / 4 с, слышимый оригинальный звук |
| Top, диапазон 990–1980 мс | PASS, 15 кадров / 15 FPS; native 3D звук тихий при этой камере |
| Повторный экспорт Front, тот же диапазон | PASS, 15 кадров; реплика, начавшаяся до start_ms, слышна |
| AAC и видео | PASS, полное декодирование каждого MP4; кадры с деталями |
| AAC против реального PCM редактора | Корреляция 0.993309; сдвиг 2.404 мс, сетка сравнения 10 мс |
| Отмена во время аудиопрохода | PASS, отменённый MP4 не опубликован |
| Окна на пользовательском desktop / foreground | 0 / 0; SwitchDesktop и input injection не используются |
| Исходная карта/мод и катсцена | SHA-256 до/после совпали |
| Завершение собственного worker | PASS; пользовательский Editor не является целью управления |
| Тесты без Editor | 15 unit/integration tests PASS, включая AAC и обрезку |
| Упакованный MCP | stdio initialize/tools/list/capabilities PASS, 11 tools |

Исходная NydusIntroBlue не содержит явных Sound-дорожек и дала настоящий тихий
PCM/AAC. Для положительного звукового теста создана отдельная копия с оригинальной
репликой Marine_Ready; пользовательские XML/мод/зависимости не изменялись.
Другой ракурс может менять громкость пространственного звука. Вырезка Front
проверяет повторную запись и звук, который начался до выбранного диапазона.

Сохраняется реальный тайминг выхода редактора, включая задержку его аудиодвижка
и тишину внутри исходной записи. Начало фонемы не приравнивается к XML start.
Проверка AAC сравнивает сигнал с записанным native PCM с его QPC-привязкой;
сэмпл-точная синхронизация по авторским XML маркерам не заявляется.

Ранее в этом изменении также проверен полный исходный NydusIntroBlue:
119 кадров / 30 FPS / 3.966667 с, 1276×716, H.264/yuv420p + AAC 48 kHz stereo;
полное декодирование и ненулевые детали кадра. Финальный EXE повторно проверен
по сценариям таблицы выше. Пользовательские MP4, XML, моды и сырые PCM не входят
в Git или публичные release assets.

Аудио — выходные буферы только собственного Editor через WASAPI, не системный
loopback и не микрофон. Выход на колонки глушится. Поддерживаются PCM 16/32 и
float32, один render stream; неизвестный формат/поток/ошибка записи завершают
экспорт ошибкой. Пустые пакеты обрабатываются по контракту Windows. Недоступное
аудиоустройство не блокирует неаудио операции; запрос аудио требует готового tap.
Сложные jumps/bookmarks, внешние связанные сцены, смена устройства в процессе
и все прочие версии Editor отдельно не сертифицированы. Были обнаружены сбои
самого Editor при избыточном повторном импорте: этот путь не используется;
аудиопроход использует штатный Restart/Play/Pause с прогревом и подтверждением.

Данные проверок остаются локально: `audio-native-04`, `audio-packaged-01` и
финальный `audio-packaged-04`. Исторические результаты ниже относятся к их версиям.

# Проверка v0.4.0 — 2026-10-20

Экспорт MP4 использует последовательную выборку кадров оригинального SC2
Editor 5.0.17.98310 на приватном desktop и установленный FFmpeg/ffprobe 8.0.
Исходники API: `app/sc2native/video.py`; нативная перемотка — `src/cutscene_bridge.inc`.

| Полная NydusIntroBlue, Front Formation Camera | PASS, 0…3965 мс → 119 кадров, 30 FPS, 3.966667 с |
| Формат | H.264 / yuv420p, 1276×716, MP4 faststart |
| Диапазон 990…1980 мс, камера Top | PASS, 15 кадров, 15 FPS, 1 с |
| Выбор диапазона/камеры через готовый API EXE | PASS, 5-кадровый и 15-кадровый MP4 |
| Полное декодирование экспортированных файлов | PASS |
| Проверка изображения из декодированного MP4 | PASS, видны модели сцены; 247 уровней яркости у полного ролика |
| Прогресс GET /cutscene/export/status | PASS, счётчик кадров растёт |

| Исходные сцена и мод | SHA-256 не изменился |
| Видимые окна/foreground события worker Editor на desktop пользователя | 0 по наблюдениям обоих live-тестов |
| Mouse/keyboard input, переключение desktop | Не используются |
| Завершение API | Принадлежащие Editor и FFmpeg завершены |

Полная сцена проверена через исходный API; для готового EXE отдельно проверены
короткий диапазон, другая камера, декодирование, скачивание и отмена. Кадр
из полного MP4 извлечён FFmpeg и проверен визуально, а не только по контейнеру.

В полном ролике 110 кадров с деталями и 9 чёрных кадров. Они сохранены в исходных
позициях таймлайна; программа не сдвигает время и не вырезает чёрные переходы.
MP4 пока без звука. Исходная временная сетка — 33 мс, readback индикатора — 10 мс.
Выходной FPS постоянный; при 60 FPS ближайшие исходные моменты повторяются.

Opt-in тест: `tests/live_video.py --template ... --scene ... --camera ... --work ...`.
Добавление `--package --smoke` проверяет готовый EXE на коротких диапазонах.
PNG/MP4, токены и полные локальные отчёты не входят в Git или релиз.

Galaxy Nydus — **341 732 байта**, SHA-256:
`0e06ea0c8a379af32fa5372a2a373353646031282f09b305b38c29de09b16aa3`.
Побайтно совпал с результатом ранее проверенного оригинального редактора.
В новом модульном API используется тот же нативный XML pipeline.

Результат PNG подтверждает транспорт из оригинального рендера, но **не** снимок
заданного ролика. Содержательной сцены в этом тесте не выбрано. Кадр чёрный;
это явно отражено в API. Управление таймлайном, камерой и выбор нужного viewport
оставлены следующим модулем и не выдаются за готовую функциональность.

Логический focus внутри приватного desktop нужен оригинальному Editor для
правильной авторской библиотеки и обновления команд. Его события отделены от
foreground рабочего стола пользователя. Мышь/клавиатура не инжектируются.

Живые моды, полные журналы, токены, runtime state и изображения пользовательского
контента не входят в Git. Скрипты opt-in тестирования находятся в `tests/`.
