# Проверка v0.4.0 — 2026-10-20

Экспорт MP4 использует последовательную выборку кадров оригинального SC2
Editor 5.0.17.98310 на приватном desktop и установленный FFmpeg/ffprobe 8.0.
Исходники API: `app/sc2native/video.py`; нативная перемотка — `src/cutscene_bridge.inc`.

| Проверка | Результат |
|---|---|
| Автоматические проверки, включая реальный H.264 encoder + decode без Editor | PASS, 13 тестов |
| Готовый windowed MCP EXE: stdio initialize/list/call/EOF | PASS, 11 инструментов |
| Полная NydusIntroBlue, Front Formation Camera | PASS, 0…3965 мс → 119 кадров, 30 FPS, 3.966667 с |
| Формат | H.264 / yuv420p, 1276×716, MP4 faststart |
| Диапазон 990…1980 мс, камера Top | PASS, 15 кадров, 15 FPS, 1 с |
| Выбор диапазона/камеры через готовый API EXE | PASS, 5-кадровый и 15-кадровый MP4 |
| Полное декодирование экспортированных файлов | PASS |
| Проверка изображения из декодированного MP4 | PASS, видны модели сцены; 247 уровней яркости у полного ролика |
| Прогресс GET /cutscene/export/status | PASS, счётчик кадров растёт |
| Отмена во время рендера | PASS, целевой MP4 не опубликован |
| Перезапись без overwrite:true | Отказ, исходный файл сохранён |
| HTTP download | SHA-256 совпал с исходным MP4 |
| Исходные сцена и мод | SHA-256 не изменился |
| Видимые окна/foreground события worker Editor на desktop пользователя | 0 по наблюдениям обоих live-тестов |
| Mouse/keyboard input, переключение desktop | Не используются |
| Завершение API | Принадлежащие Editor и FFmpeg завершены |

Полная сцена проверена через исходный API; для готового EXE отдельно проверены
короткий диапазон, другая камера, декодирование, скачивание и отмена. Кадр
из полного MP4 извлечён FFmpeg и проверен визуально, а не только по контейнеру.

В полном ролике 110 кадров с деталями и 9 чёрных кадров. Они сохранены в исходных
позициях таймлайна; программа не сдвигает время и не вырезает чёрные переходы.
MP4 пока без звука. Исходная временная сетка — 33 мс, readback индикатора — 10 мс.
Выходной FPS постоянный; при 60 FPS ближайшие исходные моменты повторяются.

Opt-in тест: `tests/live_video.py --template ... --scene ... --camera ... --work ...`.
Добавление `--package --smoke` проверяет готовый EXE на коротких диапазонах.
PNG/MP4, токены и полные локальные отчёты не входят в Git или релиз.

Поле actualTimeMs читается из индикатора Scene Time с точностью 10 мс.
Штатная команда Next Frame проверенной сборки продвигает таймлайн на 33 мс.
Кадры берутся из исходного рендера без изменения времени ради получения
нечёрного изображения. Во время прогрева допускается несколько захватов на
том же остановленном времени; чёрный/однотонный результат остаётся ошибкой.

Компиляция Nydus после катсцены вернула прежние **341 732 байта** Galaxy и SHA-256:
`0e06ea0c8a379af32fa5372a2a373353646031282f09b305b38c29de09b16aa3`.
Существующий модуль генерации/компиляции не заменён и продолжает работать.

Воспроизводимый opt-in сценарий: `tests/live_cutscene.py --package --compile-after`
с аргументами --template, --scene, --camera, --work. Полные локальные результаты,
PNG, runtime state и токены не входят в репозиторий или релиз.

Galaxy Nydus — **341 732 байта**, SHA-256:
`0e06ea0c8a379af32fa5372a2a373353646031282f09b305b38c29de09b16aa3`.
Побайтно совпал с результатом ранее проверенного оригинального редактора.
В новом модульном API используется тот же нативный XML pipeline.

Результат PNG подтверждает транспорт из оригинального рендера, но **не** снимок
заданного ролика. Содержательной сцены в этом тесте не выбрано. Кадр чёрный;
это явно отражено в API. Управление таймлайном, камерой и выбор нужного viewport
оставлены следующим модулем и не выдаются за готовую функциональность.

Логический focus внутри приватного desktop нужен оригинальному Editor для
правильной авторской библиотеки и обновления команд. Его события отделены от
foreground рабочего стола пользователя. Мышь/клавиатура не инжектируются.

Живые моды, полные журналы, токены, runtime state и изображения пользовательского
контента не входят в Git. Скрипты opt-in тестирования находятся в `tests/`.
